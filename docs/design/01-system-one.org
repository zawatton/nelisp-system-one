* 1. What this is, and what it is not

On 2026-09-15 TypeSafe AI announced =Jev=, the first model of a category they
call *System One models*: a model that takes unstructured program state as
input and returns a *typed, probabilistic decision* in a single parallel pass,
instead of emitting text one token at a time.

This document is *not* a plan to reproduce Jev.  Jev cannot be reproduced:

| artifact                         | availability                          |
|----------------------------------+---------------------------------------|
| model weights                    | closed -- hosted API, early access     |
| training method (RLCD)           | named only; no paper, no details      |
| architecture specifics           | not published                         |
| self-hosting                     | not offered, not documented           |
| public                           | API surface, Python/JS SDKs, 3 primitive types |

RLCD is expanded by the vendor as /Reinforcement Learning for Calibrated
Decisions/ and nothing further is said about it.  Any claim in this repository
to have "implemented RLCD" would be unfounded, and must not be made.

What *is* reproducible is the *category*.  The vendor's own description of a
System One model decomposes into four separable claims, and they do not share a
fate:

| # | claim                                          | reproducible here? | why                                                |
|---+------------------------------------------------+--------------------+----------------------------------------------------|
| a | output is a value of a pre-declared type       | *yes, structurally* | if the output space is an enumeration, a type error is unrepresentable, not merely rare |
| b | one parallel forward pass, no autoregression   | *yes, architecturally* | a decision head over a pooled encoder needs no decode loop |
| c | probabilities are calibrated                   | *yes in effect, no in method* | calibration is measurable and trainable by standard means; RLCD itself is unavailable |
| d | 40-200x faster, $0.042/MTok, output free       | *no*                | that is a serving-infrastructure claim about their cluster |

Claim (a) is the interesting one, because it is the one usually stated loosely.
"Cannot hallucinate" is true of a System One model in exactly one sense: it
cannot emit a token sequence that fails to parse into the declared type, because
it never emits tokens.  It can still be *wrong* -- it can pick the wrong option
with high confidence.  Calibration, claim (c), is what turns that from a defect
into a usable signal, and it is the only one of the four that requires real
research effort here.  The rest is engineering.

Claim (d) does not transfer and must never be quoted as if it did.  What can
honestly be measured in this repository is the *relative* cost of one pooled
forward pass against an autoregressive decode of the same decision on the same
substrate.  That ratio is structural -- it is the reason the vendor's number is
large -- and it survives the move to a slow interpreter, even though the
absolute latency will not be remotely competitive.

* 2. The primitives, as types

The vendor exposes three question types.  Restated as Elisp signatures:

#+begin_src elisp
;; Choice -- pick exactly one option from a declared set.
;;   Returns the chosen option, a probability for EVERY option, and a
;;   confidence.  Cardinality is capped (the vendor caps at 255).
(nso-choice STATE CRITERIA OPTIONS)
  => (:choice OPTION :probabilities ((OPTION . P) ...) :confidence C)

;; Score -- rate against ordered, described levels.
;;   The levels are ORDINAL, not merely categorical: "poor < fair < good"
;;   carries information a plain softmax over three labels discards.
(nso-score STATE CRITERIA LEGEND)
  => (:score LEVEL :probabilities ((LEVEL . P) ...) :confidence C)

;; Noul -- a yes/no question.  Returns P(yes).
(nso-noul STATE QUESTION)
  => (:p-yes P :confidence C)
#+end_src

Two observations that shape the whole design:

- *All three are the same object.*  Noul is Choice over =(yes no)= with the
  answer reported as a single probability.  Score is Choice with an ordering
  imposed on the options.  There is one head, with two specialisations, not
  three architectures.

- *Probability and confidence are different quantities and must not be
  conflated.*  The per-option probabilities are a distribution over the answer;
  confidence is a scalar about that distribution.  A uniform distribution over
  two options and a uniform distribution over two hundred both have a "most
  likely" option, but they are not equally uninformative.  Defining confidence
  as =max p= silently makes the 200-way question look catastrophically
  unconfident and the 2-way question look adequate, when the 200-way answer may
  carry far more information.  §4 fixes a definition; the point here is that it
  is a *design decision*, not a readout.

* 3. Architecture

The plan is a *frozen donor encoder plus a typed decision head*.  No
pre-training.  The sibling =nelisp-llm= repository (Doc 8, phases 0-2d SHIPPED,
phase 3 in progress) already imports Qwen3-0.6B as a 571 MiB int8 table, runs
all 28 layers on the GPU, and trains a LoRA over the frozen base.  That is the
substrate this repository consumes.

** 3.1 Why not the obvious thing

The obvious implementation is an =N=-way softmax head: a linear from the pooled
hidden state to =N= logits.  It is wrong here for a specific reason -- the
option set is *per query*, not per model.  A fixed =N=-way head would have to be
retrained for every new question, and it has no way to use the option's own text
("expired" vs "option_3").

The head therefore *scores options against the state* rather than classifying
the state into slots:

#+begin_example
  state text ──► frozen encoder ──► pool ──► s  (dim d)
  option text ─► frozen encoder ──► pool ──► o_i (dim d)   for each option

  logit_i = <W_s · s , W_o · o_i> / sqrt(d) + b(o_i)
  p       = softmax(logit_1 .. logit_N)
#+end_example

This handles a variable option set, an option set never seen in training, and
options whose text is informative -- at the cost of one encoder pass per option.
Since options are typically short and highly reusable, they cache: an option
embedding depends only on the option text, so a routing table of 20 options is
embedded once and reused for every query.  The per-query cost stays *one* state
pass, which is the property claim (b) rests on.

The 255 cardinality cap is worth adopting, not because of a kernel limit but
because it is a useful contract: it bounds the attention-free scoring loop and
makes the "embed every option" cost predictable.

** 3.2 Pooling

/Settled by P1's measurements; the original reasoning is kept because it was
wrong in an instructive way./

The first draft argued that a causal donor favours the last-token state, since
that is the position the next token is read from, and it named the learned
attention pool as the sophisticated option.  Measured, on the same task and the
same forward passes: *mean and last are close, the learned pool loses badly,
and the depth the states are taken from matters more than the pooling.*  Mid
depth (layer 14 of 28) beat the final layer for both parameter-free poolings --
0.870 against 0.761 for last, 0.848 against 0.783 for mean.  The final layer is
specialised for predicting the next token, which is not the same thing as
representing the sentence.

The attention pool, the only variant with parameters of its own, is *not
decided by P1*.  Its outcome depends on whether one fixed learning rate suits
the feature scale, and standardising its inputs swaps which depth fails --
mid 0.476 to 0.857 held-out, final 0.702 to 0.512.  Deciding it needs a
learning rate chosen per configuration, which is the hyperparameter search P1
ruled out; that belongs to P2.  When it does train it ties the best
parameter-free pooling, so it is not redundant either.  See the P1 entry in
section 6.

** 3.3 Ordinal heads for Score

Score's levels are ordered, so a plain softmax throws away the constraint that
confusing "good" with "excellent" is a smaller error than confusing it with
"poor".  The standard fix is a cumulative-link head: predict =K-1= thresholds
and read the level probabilities as differences of a monotone CDF.  Ordering is
then structural, not learned, which is the same argument as claim (a) one level
down.

P2 must show this beats the plain softmax on an ordinal task, or drop it.  A
mechanism that costs complexity and buys nothing measurable does not ship.

*Measured 2026-09-21, and dropped.*  On the held-out split of
=data/score-commitment.eld=, with both heads converged and fitted on identical
features under identical rules, the cumulative-link head is *worse*: MAE 0.733
against the nominal softmax's 0.373, a paired bootstrap difference of −0.360
with a 95% interval of [−0.560, −0.147] that excludes zero in the softmax's
favour.  The argument above is not wrong about what ordering *is*; it is wrong
about what it *buys here*.

Two readings survive the result and one does not:

- What dies is the parameter argument.  The ordinal head's economy -- one
  shared direction plus K−1 cutpoints, 1028 parameters against 5120 -- is
  exactly what costs it.  Five levels of epistemic commitment are apparently
  not one direction in this encoder's space with four thresholds on it, and
  forcing them onto one loses more than the extra parameters cost.
- What survives is that the *task* is ordinal, which is why MAE is the metric
  the comparison is made on at all.  A nominal head that happened to be right
  and wrong at random would show it here; this one does not, and its errors are
  mostly to an adjacent level.

The honest scope: this is one encoder, one dataset of 240 template-regular
sentences, and n=75 held out.  It refutes the claim *as this section made it*
-- that the cumulative-link form should be preferred -- and does not establish
that ordinal heads are useless in general.  Section 2's =nso-score= signature is
unaffected: Score still returns a distribution over ordered levels, and the
head behind it is now the nominal one.

* 4. Calibration -- the actual work

Everything above is engineering with a known answer.  This section is not.

** 4.1 What "calibrated" has to mean

A model is calibrated if, among all the answers it gave probability 0.7, about
70% are right.  This is an empirical property of a model *and a distribution of
inputs*, which means:

- calibration is measured on *held-out* data, never on the training set;
- a model calibrated on one task's input distribution is not thereby calibrated
  on another's;
- a *claim* of calibration without a named evaluation distribution is vacuous.

** 4.2 Training and post-hoc correction

Two mechanisms, in order:

1. *Proper scoring rule as the training objective.*  Negative log-likelihood and
   Brier score are both minimised, in expectation, by reporting the true
   probability -- that is what "proper" means.  Training a decision head with
   NLL is therefore already calibration pressure; accuracy-only objectives are
   not.
2. *Post-hoc temperature scaling.*  A single scalar =T= dividing the logits,
   fitted on a held-out split.  It cannot change any answer (it is monotone, so
   argmax is invariant) and typically removes most of the miscalibration of a
   neural classifier.  Vector scaling (per-class affine) is the next step up and
   *can* change answers, so it needs its own accuracy check.

Neither is RLCD.  Both are standard, reproducible, and sufficient to support the
only claim this repository will make: /the reported probabilities are calibrated
on the stated evaluation set, to the stated ECE/.

** 4.3 The gate, and the trap in the gate

/Revised 2026-09-19 against P0's measurements.  The first draft of this section
asserted two things that turned out to be wrong in opposite directions; they are
corrected here, with the numbers that corrected them./

Expected Calibration Error is a binned statistic, so a bare ECE is not a result.
What the binning does, measured on the P0 stubs (=test/calibration-test.el=):

- *Too few samples per bin biases the estimate away from zero, not toward it.*
  Per-bin accuracy is a noisy estimate of per-bin confidence, and the summand is
  an absolute value, so the noise has nowhere to cancel.  A stub that is
  calibrated /by construction/ scores 0.0876 at =n=100= and 0.0109 at =n=4000=
  (mean over 6 seeds, 10 equal-width bins).  The earlier claim that scarce data
  biases ECE /low/ was backwards.

- *Too few bins biases it toward zero*, and that is where "a miscalibrated model
  can look calibrated" actually comes from.  =nso-stub-cancelling= is
  underconfident by 0.30 on half its inputs and overconfident by 0.30 on the
  other half; at one bin it scores *0.0005* and at ten bins *0.2945*.  Coarse
  bins let opposite errors cancel.

- *The scheme -- equal-width against equal-mass -- often does not matter at all.*
  When the gap keeps one sign across the whole confidence range, the absolute
  value comes outside the weighted sum and ECE collapses to =|mean confidence -
  mean accuracy|=, which no partition can change.  Measured on the
  4x-overconfident stub, equal-width/10, equal-mass/10, equal-mass/20 and the
  collapsed expression agree to 1e-9 (0.266760984).  Equal-width/50 comes out
  higher, at 0.269090 -- not a scheme effect but the first bullet again, one bin
  having flipped sign on noise.  So the earlier instruction to pick a scheme and
  never switch it is not wrong, but it guards the wrong parameter: *the bin count
  is the load-bearing one*, and both matter only where the sign of the gap
  changes.

- *No partition can report less than the global gap*, by the triangle
  inequality.  A bin count can therefore hide miscalibration but never invent
  it, which is the one direction in which a coarse ECE is safe to trust.

So the gate is: *ECE on a named held-out set, with the bin count, the binning
scheme and n stated beside it, plus a reliability diagram* -- and the diagram is
the part a human reads, because it is what shows a sign change that the scalar
has averaged away.

** 4.4 Negative control (mandatory)

This repository inherits a rule from its siblings: a check that has never been
seen to fail is not evidence.  Before any calibration result is believed, the
calibration gate must be run against a *deliberately miscalibrated* model -- the
simplest being the same model with its temperature set to 0.25 or 4.0 -- and it
must go red.  A calibration harness that reports "well calibrated" for both the
real model and a 4x-overconfident one is measuring nothing, and this failure is
easy to ship because the passing case looks identical either way.

The same discipline applies to the type-safety claim: the suite must contain a
head deliberately allowed to emit an out-of-set answer, and the type gate must
catch it.

* 5. What this cannot do

A System One model gives up string generation.  It cannot summarise, cannot
explain its answer, cannot write code, cannot answer an open question.  The
vendor states this plainly and it is not a limitation to be engineered around --
it is the trade that buys the single pass.

The consequence for this repository is that a System One model is a *decision
layer*, never a replacement for a language model.  Its use is the case where the
answer set is known in advance and the same question is asked many times over a
shared state.

** P1 -- Noul, end to end [SHIPPED 2026-09-19]

Frozen Qwen3-0.6B encoder + pooling + a single scalar head.  LoRA fit on a yes/no

*** The answer

*A frozen 0.6B causal donor pools into something a linear head can use, and
what it carries is sentence meaning rather than word identity.*

The best configuration reaches *0.857* held-out against a majority baseline of
exactly *0.500*, interval [0.767, 0.916].  On the compositional subset -- pairs
whose two members share their polarity words and differ only in how those words

means no selection can have leaked.

*** Chasing the attention pool: a refuted hypothesis and the real cause

The unexplained row was =mid/attn=, which did not fit at 140 examples or at
252, on data every other configuration memorised completely.  Section 4.4 had
recorded a hypothesis -- scale: real hidden states are large, so =softmax(u . h)=
saturates on the first step and the gradient, which carries a factor
=a(1 - a)=, vanishes.  Mid-depth activations being the larger ones would then
explain why mid alone fails.

*The hypothesis was written as four predictions before anything was measured*,
with the rule that all four had to hold (=tools/attn-scale-probe.el=, which
reads the saved states and needs no GPU):

| # | prediction                                        | final  | mid    | verdict |
|---+---------------------------------------------------+--------+--------+---------|
| 1 | mid-depth states are larger                       | 2.976  | 3.725  | holds   |
| 2 | mid-depth score spread is wider                   | 0.1735 | 0.2921 | holds   |
| 3 | mid-depth softmax is nearer one-hot               | 0.1266 | 0.1350 | holds   |
| 4 | mid-depth |du| at initialisation is smaller       | 0      | 0      | *refuted* |

Three held and the hypothesis is still dead, which is the argument for writing
the predictions down first.  Prediction 1 holds at a ratio of 1.25; had that
been the only thing looked at, it would have read as confirmation.  What the
other rows say is that the mechanism is absent: a uniform softmax over these
sequences is 0.1149, and the measured peak is 0.1350, so the pool starts very
nearly flat and never saturates at either depth.  And =|du|= is *exactly zero*
at both depths at initialisation -- because the head is zero-initialised, so
=da_i = g (w . h_i) = 0= and every term of =du= vanishes.  A quantity that is
identical at the two depths cannot explain a difference between them.

That zero was the useful part.  Looking for what else differed turned up an
asymmetry that had been there since the head was written: *=attn= was the only
path in this repository fitting on raw features.*  =last= and =mean= hand
their pooled vectors to `nso-probe-fit-and-score', which standardises before
fitting; the joint model trained straight on hidden states with an RMS near 3.
Both paths used the same learning rate, 0.5.

Measured across learning rates (=tools/attn-lr-probe.el=, 200 steps):

| depth | lr    | train acc | loss   |
|-------+-------+-----------+--------|
| final | 0.5   |     0.500 | 19.28  |
| final | 0.1   |     0.500 | 18.04  |
| final | 0.02  |     0.500 | 13.66  |
| final | 0.005 |     0.500 |  4.447 |
| mid   | 0.5   |     0.500 | 14.17  |
| mid   | 0.1   |    *0.976* |  7.348 |
| mid   | 0.02  |     0.500 |  2.177 |
| mid   | 0.005 |     0.500 |  0.695 |

A cross-entropy of 19 is not a model that failed to learn, it is one that is
confidently wrong: divergence.  A loss of 0.695 is =ln 2=, a model that has
not moved.  Between them is a narrow window, and at mid depth lr 0.1 lands in
it and reaches 0.976.  So the failure was step size, not representation.

Standardising the states before the pool -- giving =attn= the conditioning the
other two always had, with statistics from the fit rows only -- confirmed it in
the sharpest available way: *it swapped which depth fails.*

| conditioning        | final/attn train | held-out | mid/attn train | held-out |
|---------------------+------------------+----------+----------------+----------|
| raw states          |            1.000 |    0.702 |          0.500 |    0.476 |
| standardised states |            0.518 |    0.512 |          1.000 |   *0.857* |

A result that inverts when the inputs are rescaled is a result about the
optimiser.  Neither row measures the pooling, so *the attention variant is
undecided* and P1's earlier claim that it loses is withdrawn.

Deciding it fairly needs a learning rate chosen per configuration on a
validation split, which is exactly the hyperparameter search P1 ruled out to
keep selection from leaking.  That is a real cost and it belongs to P2, with
the reason recorded rather than the search quietly added here.  What can be
said already: on the one setting where it trains, the learned pool is
competitive rather than redundant -- 0.857 held-out, the table's best
post-temperature ECE at 0.020, and its best antonym accuracy at 0.972.

The first full encode took 39.7s per example and the probe's two attention

One hypothesis was wrong and is recorded because being wrong quickly was the
useful part: the first guess at the probe's cost was allocation churn, 67,200
kilobyte vectors per training run.  Hoisting them out moved 39.6s to 40.3s.
Measuring said so immediately; reasoning would have said "fewer allocations,
therefore faster" and stopped there.

*** Two defects the controls caught before they reached this table

Both were found by running the probe over *synthetic noise* at full scale
(=tools/p1-fake-states.el=), where every held-out number must come out at
chance.  Neither produced an error; both produced plausible-looking numbers.

1. *The temperature was fitted on the training split's own logits.*  The head
   has already separated those, so the NLL-optimal temperature there is a
   /sharpening/ one.  On noise it returned T = 0.13 and drove held-out ECE from
   0.169 to 0.451.  The code carried a comment explaining why it was not fitted
   on held-out -- the leak was correctly avoided and a broken alternative
   chosen in its place.  Fixed by fitting on out-of-fold logits from within the
   training split.

2. *Fixing that moved the leak rather than removing it.*  The attention pool's
   direction was still trained on the whole training split, so the out-of-fold
   head scored features that had already seen the fold; =attn= alone still came
   back with T = 0.21 and ECE 0.346 while the fixed poolings reached 0.011 and
   0.073.  The featurizer is now refit per fold, pooling included.

Both are pinned by tests that fail if the old behaviour returns, and the second
test was mutation-checked against a deliberately broken implementation.

*** The control, re-run against the shipped code

The two defects above were found with earlier versions of the probe, so the
control was run again end to end after the fixes -- the same 140 rows, the same
1024 dimensions, the same two depths, with noise where the hidden states would
be.  Every held-out number must come out at chance, and every temperature must
flatten rather than sharpen.

| depth | pooling | train acc | held-out acc |        95% CI | ECE   | after T |      T |
|-------+---------+-----------+--------------+---------------+-------+---------+--------|
| final | last    |     1.000 |        0.522 | [0.381,0.659] | 0.169 |   0.011 | 20.00* |
| final | mean    |     1.000 |        0.587 | [0.443,0.717] | 0.189 |   0.073 |  15.71 |
| final | attn    |     1.000 |        0.522 | [0.381,0.659] | 0.122 |   0.014 | 20.00* |
| mid   | last    |     1.000 |        0.500 | [0.361,0.639] | 0.207 |   0.012 | 20.00* |
| mid   | mean    |     1.000 |        0.543 | [0.402,0.678] | 0.147 |   0.032 | 20.00* |
| mid   | attn    |     1.000 |        0.522 | [0.381,0.659] | 0.130 |   0.013 | 20.00* |

Four things this says:

- *No configuration finds signal in noise.*  Held-out accuracy spans 0.500 to
  0.587 and every interval contains 0.5.  The 0.870 in the results table is not
  an artefact of the pipeline.

- *The attention fix holds.*  Before it, =attn= on this same data returned
  T = 0.21 and drove ECE from 0.122 to 0.346.  It now returns a flattening
  temperature and 0.122 -> 0.014, like every other row.

- *Every row memorises the training split completely.*  Train accuracy 1.000 on
  pure noise is the precondition for the calibration trap: the probe has ample
  capacity, the logits come out confident, and only the held-out column knows
  otherwise.

- *A temperature at the bound is the correct answer here.*  With no signal the
  honest distribution is flat, so the optimum is past 20 and the search returns
  its ceiling.  Five rows do.  This is why the figure is marked rather than
  printed as a fit.

One row was worth flagging at the time.  On noise, =mid/attn= trains to
1.000; on the real mid-depth features it reached 0.532 at 140 examples and
0.500 at 252, never fitting at either size.  /Resolved: the cause was the
learning rate meeting unstandardised features, not the features themselves --
see "Chasing the attention pool" above.  The scale hypothesis sketched in the
rest of this paragraph was measured and refuted./
So the failure there is not a capacity limit of the model class -- random
features of the same shape fit perfectly.  The plausible cause is scale: real
hidden states carry magnitudes in the hundreds, so =softmax(u . h)= saturates
to a near one-hot pool on the first step and the gradient through it vanishes,
where noise features in [-0.5, 0.5] never saturate.  That is a hypothesis, not
a measurement, and normalising the pool scores before the softmax would test
it.  P2 should either do that or drop the learned pool.

And one caution the control illustrates better than the results table does:
on *pure noise*, =final/last= scores *0.900* on the compositional subset.  With
n = 10 a single example is ten points, and a striking number there means
nothing at all.

*** Choice: NOT ACCEPTED, and the reason is not the one the numbers first said

*** What the first numbers were, and why they were not an answer

The first run reported 0.250 held out on four options -- exactly chance -- and
0.000 against twelve.  It would have been easy to write that up as section
3.1's architecture failing.  One number forbade it: *training* accuracy was
0.250 on an eight-way task where chance is 0.125.  The head had not fitted the
data it was fitted on, and a model that did not train says nothing about
whether its design generalises.  That is the same trap P1 fell into over the
attention pool, one phase earlier.

Diagnosed (=tools/p2-fit-probe.el=), the shipped setting had diverged:

| states       | lr    | train acc | loss  |
|--------------+-------+-----------+-------|
| raw          | 0.5   |     0.219 | 27.8  |
| raw          | 0.02  |     0.521 | 2.525 |
| standardised | 0.5   |     0.542 | 1.844 |
| standardised | 0.001 |     0.188 | 2.694 |

A cross-entropy of 27.8 is divergence.  So the first P2 table measured an
optimiser, not an architecture, and it is not reported above.

*** Why the head still does not fit after that is fixed

Two geometries, measured on the encoded states:

| embeddings | mean pairwise cosine | min   | max   |
|------------+----------------------+-------+-------|
| options    |                0.683 | 0.572 | 0.848 |
| states     |                0.923 | 0.859 | 0.966 |

The states sit in a narrow cone.  The Noul head of P1 survived that because a
binary decision needs one direction; separating eight does not.  Standardising
centres the cone away and is now what the probe does, which lifts training
accuracy from 0.250 to 0.385 -- real signal at three times chance, and still
not a fit.

The synthetic suite reproduces the geometry exactly (mean cosine 0.923, RMS 4)
and *fits it completely*: standardised, the head reaches 1.000 there against
0.487 raw.  So the remaining gap is not scale and not conditioning.  It is
that the donor's pooled request states and its pooled topic-label embeddings
do not stand in the relation this head assumes -- the state does not point at
its own option's direction the way a synthetic state does.

*** One hypothesis tested and refuted

The below-chance held-out accuracy invited an obvious explanation: the
option-only term =c . o_i= is a score for an option with no reference to the
state, a learned prior expressed through embeddings rather than indices, and
such a prior is arbitrary on options it has never seen -- arbitrary in a fixed
direction, which is how a head lands below chance rather than at it.

Freezing =c= at zero (=NSO_P2_FREEZE_C=, an ablation now in
`nso-choice-train') changes nothing: held-out stays at 0.104 either way.  The
hypothesis is refuted and the below-chance behaviour comes from the gate
itself.

*** Descriptions instead of labels: the gap closes, the transfer does not

The diagnosis above named the two-word option label as the suspect: pooling
"weather forecast" and a ten-word request through the same causal encoder and
expecting a shared geometry was an assumption.  Each topic now also carries a
=:description= of eight to twelve words, in the register of a request, and
both forms are encoded so either can be selected (=NSO_P2_OPTION=) from one
states file.

The geometry moved, and by most of the distance:

| option form  | mean pairwise cosine |
|--------------+----------------------|
| labels       |                0.683 |
| descriptions |                0.844 |
| (states)     |                0.923 |

And the pathology went with it:

| evaluation             | labels | descriptions | chance |
|------------------------+--------+--------------+--------|
| seen topics, training  |  0.385 |        0.344 |  0.125 |
| held-out topics        |  0.104 |    *0.229*   |  0.250 |
| held-out vs all topics |  0.042 |        0.042 |  0.083 |

Held-out accuracy was *below* chance with labels and is *at* chance with
descriptions -- 0.229 with an interval of [0.133, 0.365], which contains
0.250.  The systematic anti-correlation is gone.  Transfer is not there.

So the distributional mismatch was real and it was not the binding
constraint.  With the geometry largely matched, a diagonal bilinear form still
cannot read topic identity out of these pooled states.  That is a sharper
statement of the P2 result than the label run supported, and it rules out the
cheapest of the three remedies listed below; the other two -- more than
diagonal capacity, and whitening rather than per-axis standardisation -- are
untouched.

*** A guard that measured the wrong thing

The encode for this run failed once, and the response was a guard that refused
any resident load faster than twenty seconds, on the reasoning that 568 MiB
cannot upload in two.  It had a negative control and the control passed.  It
was still wrong: it blocked the next legitimate run, and checking properly --
one layer's GPU block against `nl-llm-wgpu-block-cpu', which reads the weights
on the host -- showed the handles were correct to a relative 4e-9 after a
load of one second.  Page cache, not a broken upload.

The negative control had confirmed that the check fires below its threshold.
It could not confirm that the threshold stood for anything, because *timing
was a proxy*.  What the run needs to know is whether the handles compute the
weights, so that is what `nso-encode-check-layer' now asks, once per run, for
a few seconds.  Speed is no longer consulted in either direction.

The original failure remains unattributed: it did not recur, and a standalone
repro of the same layer at the same sequence length passes.  It is not claimed
as fixed.  What changed is that a run whose handles are not backed by the
weights now stops at the first layer instead of dying minutes later with an
index error in the FFN path.

*** What this does and does not establish

- It does *not* establish that option-scoring fails as an architecture.  The
  synthetic suite still shows the property that motivated section 3.1: a head
  fitted on five option directions reaches 1.000 on five it has never seen,
  and 0.942 on twelve.  The principle works where the state genuinely points
  at its option.
- It *does* establish that a frozen Qwen3-0.6B, pooled by the P1 recipe, does
  not produce request states and topic-label embeddings that live in such a
  relation.  Pooling a two-word label and a ten-word request through the same
  causal encoder and expecting a diagonal bilinear form to align them was an
  assumption, and it is the assumption that failed.

What would test it properly: pooled option embeddings built from descriptions
rather than two-word labels; a shared projection with more than diagonal
capacity, which needs more than 144 examples to fit; whitening rather than
per-dimension standardisation, since the cone is a covariance structure and
not a per-axis one.  Each is a phase of its own.

*** The second time a synthetic suite hid a real-scale failure

=test/choice-test.el= passed 9 of 9 -- including unseen options at 1.000 --
while the shipped setting diverged on real features.  It used unit-norm
directions; the real states have RMS 4 and sit in a cone.  P1's attention pool
was the first instance of exactly this.  Twice is a pattern, not luck, so the
suite now carries a realistic-scale case that reproduces the geometry and
pins what actually happens there.

One assertion in that new case was written before measuring and was wrong: it
demanded that raw features blow the loss up threefold, and the synthetic only
loses half the fit rather than diverging outright.  It now asserts the effect
that reproduces.

*** Score -- pre-registered 2026-09-20, before the encode ran

**** The reason this was deferred does not apply to it

This section previously read "not started", on the grounds that Choice had
failed and building the ordinal head on an unsound foundation would be
premature.  That reasoning was wrong, and it is worth saying why rather than
just proceeding.

Choice failed at a specific thing: aligning *option embeddings* with *state
embeddings* in one space, through a diagonal bilinear form, when both come out
of the same frozen causal encoder whose states have mean pairwise cosine 0.923.
Score has no option embeddings.  Its legend is fixed, and the levels enter the
model as K-1 scalar cutpoints fitted alongside a single weight vector.  There
is no cone to align and no per-query option set to generalise over.  The two
primitives share a commentary in §2 and almost nothing in their failure modes.

Deferring Score because Choice failed was reasoning from "they are both in P2"
rather than from what either actually does.

**** What was built

=lisp/nso-score.el=, a cumulative-link head exactly as §3.3 specifies:

: f(x) = w . x        c_k = sigma(theta_k - f)        p_k = c_k - c_{k-1}

with =dim + (K-1)= parameters against a nominal softmax's =K*dim=.  Two
decisions worth recording because they are not free:

- *Ordering is enforced by construction*, =theta_k = theta_{k-1} +
  softplus(d)=, so a non-distribution is unrepresentable rather than merely
  penalised.  That is claim (a)'s move, made in the parameterisation instead of
  at the boundary.  A penalty would have left the failure possible and silent.
- *No bias in f.*  A constant added to f shifts every cutpoint equally, so a
  bias makes the parameterisation non-identifiable and hands gradient descent a
  flat direction.  Two runs would then differ for a reason that is not the
  data.

The gradient is derived by hand and =test/score-test.el= checks it against
central finite differences on every parameter block before checking anything
downstream of it.

**** Two defects the build found

Neither is about Score.  Both had been sitting in shipped code.

1. *The type gate was blind to Score.*  =nso--validate-choice= read the answer
   under =:choice=; §2 gives Score the signature =:score=.  So a well-formed
   Score answer was rejected and an ill-formed one -- reported under the wrong
   key -- was accepted.  The P0 suite agreed with the gate, because its three
   Score checks were written from the implementation and two of them only ever
   asked the gate to say no.  A suite written from the implementation cannot
   find a disagreement with the specification, however much of it there is.
   Fixed by =nso--answer-key=; the suite now checks the accept direction and
   checks that each rejection names the right reason.

2. *An ordinal temperature can change the answer.*  §4.2 relies on temperature
   being monotone in the logit, so it buys calibration without spending
   accuracy.  That does not carry over: here each probability is the increment
   of sigma across an interval, and dividing every margin by T rescales all the
   intervals at once, so which interval collects the most mass moves.  Margins
   =(-10, -3, 0.1, 0.2)= report level 2 at T=1 and level 4 at T=5.  The
   commentary claimed the opposite by analogy with the binary case, and the
   test caught it.  Consequence for this phase: accuracy is reported on both
   sides of any temperature.

**** The dataset, and a bound rather than a hope

=data/score-commitment.eld=: 16 scenarios x 15 sentences = 240 examples, exactly
48 per level and exactly 3 per level per scenario, so the majority baseline is
0.200 and the best constant answer is the middle level at 1.200 MAE.  Split by
scenario, every third held out: 165 train, 75 held out.

The hard half is built so that a bag of words provably cannot do well.  Every
hard sentence has a partner in its own scenario whose *set of words is
identical*, because the matrix clause already carries "not" and flipping the
embedded clause's polarity adds a second one that a set-valued bag cannot see:

| sentence                                  | level     |
|-------------------------------------------+-----------|
| I do not doubt that E will arrive         | certain   |
| I do not doubt that E will not arrive     | ruled out |
| It is not true that E will arrive         | ruled out |
| It is not true that E will not arrive     | certain   |
| It is not unlikely that E will arrive     | likely    |
| It is not unlikely that E will not arrive | unlikely  |

Two inputs a model cannot distinguish must receive the same answer, so each
unequal pair yields at most one correct answer.  That bounds *any* bag-of-words
model, at any capacity, at **0.600 accuracy and 1.200 MAE** on the hard subset
-- and 1.200 is the constant answer's MAE, so on that half a bag of words can
do no better than ignoring the sentence.  The generator recomputes the bound
from the sentences and refuses to emit a file whose hard half is not fully
paired.

=tools/score-lexical-check.el= measured it before any GPU time was spent: the
nominal head on unigrams reaches exactly 0.600 and 1.200.  The bound is tight,
which is what makes anything above it evidence of word order.

***** The third time a check fired without measuring the right quantity

The first version of this dataset used "no doubt" against "no chance" and
claimed a bag of words could not separate them.  The generator's check agreed
-- it compared the *negation words present*, ignoring that "doubt" and "chance"
are themselves features.  The claim held for a single shared score, which is
what the ordinal head has, and failed for one weight vector per level: a
five-way softmax scored 0.800 on that subset.  The check fired on what it
measured and was measuring the wrong thing, which is now the third instance in
this repository (§10.6, fault 3).  The lexical pre-flight caught it in seconds
instead of after an hour of encoding, which is the only reason it is a
paragraph here rather than a retraction below a results table.

The replacement is a bound rather than an argument, which is the difference
that matters: it does not have to be re-argued when someone fits something
bigger.

**** Pre-registered acceptance

Committed before the encode runs.  One configuration, fixed now so the result
is not the best of six: *mid layer (13), last-token pooling* -- what P1
shipped.  Both heads trained on identical standardised features with identical
steps, learning rate and L2.

- *Gate 0, convergence.*  Both heads must finish with gradient norm below 0.05.
  If either does not, the comparison is void and reported as void rather than
  reported.  Four results in this repository turned out to be measurements of
  an unconverged optimiser.
- *Gate 1, the negative control (§4.4, mandatory).*  The same pipeline on
  shuffled levels must reach chance accuracy and no better than the constant
  answer's MAE.  If it does not, nothing else here is read.
- *Gate 2, the ordinal claim.*  §3.3 requires the cumulative-link head to beat
  the plain softmax on an ordinal task "or drop it".  Accepted when the 95%
  paired bootstrap interval for =MAE(nominal) - MAE(ordinal)= excludes zero in
  the ordinal head's favour.  If it excludes zero the other way, the ordinal
  head is dropped and §3.3 is rewritten; if it straddles zero, §3.3's claim is
  unsupported at this n and that is what gets written.
- *Gate 3, composition.*  Held-out MAE on the *hard subset* strictly below
  1.200, with the upper end of its 95% bootstrap interval also below 1.200.
  1.200 is not a chosen threshold: it is the floor the pairing imposes on every
  bag-of-words model.  Accuracy against the 0.600 ceiling is reported as a
  secondary reading, not a second chance to pass.

Reported, and explicitly *not* gates:

- Calibration, by P3's binning-free gain against a calibrated-by-construction
  band at n=75.  ECE is not used: P3 established it is unmeasurable at this
  size, and no threshold set now, after the head exists, would be a
  pre-registration.  Accuracy and MAE are reported before and after the
  temperature, because here it can change them.
- The fraction of held-out distributions that are unimodal.  The
  parameterisation does not guarantee it and the commentary does not claim it.
- MAE under the mode against MAE under the median.  §2's shared contract
  requires the argmax; the median is what minimises absolute error.  If the
  median wins, that is a cost of the shared contract and belongs in §2.
- The easy subset, from which nothing is claimed: a unigram nominal head
  already scores 1.000 on it.

- *Calibration.*  T = 4.239 fitted out of fold, NLL 2.4003 → 1.3128, a gain of

***** Two void runs, and what they were worth

Gate 0 voided the first two probes.  Both times it was a constant chosen against
synthetic data meeting a real scale, and both times the gate caught it before
any comparison was read.

| run | what broke                              | ordinal \vert g \vert | held-out MAE |
|-----+-----------------------------------------+-------------+--------------|
|   1 | fixed step 0.5 overshoots at dim 1024   | 4.79        | 1.147        |
|   2 | 600 iterations is not convergence here  | 0.141       | 0.867        |
|   3 | line search, stop on the gradient norm  | 4.99e-03    | 0.733        |

The suite fitted at dim 16 and the GPU-free smoke at dim 64; the encoder
produces dim 1024, where a standardised feature vector has norm 31 and a step
of 0.5 overshoots every iteration.  The smoke had deliberately matched the real
states' *scale* -- RMS 4, with a comment explaining why -- and not their
*dimension*: half a lesson applied is how a fixture stays green through the
failure it exists to catch.  That is the fourth time here that a constant
chosen on synthetic data lost to a real scale, and the third time a green suite
sat above a broken shipped setting.

The fixes were to remove the constants rather than re-choose them.  Both heads
now use the same Armijo backtracking line search, so the fit does not depend on
the step being right, and both stop when the gradient norm falls an order of
magnitude inside gate 0 rather than after a fixed number of iterations.  The
iteration cap rose from 600 to 6000, which amends a committed protocol, so:
the budget was chosen by sweeping the *training* gradient norm at
600/1200/2400/4800 before any held-out number was read, it applies to both
heads under one rule, and it cannot buy a favourable gate 2 -- the nominal head
is at 5e-07 by iteration 600 and its training loss does not move by a digit in
the 4200 after that, so the only head a larger cap can help is the ordinal one,
which is the head gate 2 is about.

Note what the two void runs did *not* do: they did not produce a number that
went into a table.  Run 1's ordinal head scored 0.307 and run 2's scored 0.360,
and neither is quoted as a result anywhere above.  That is the entire purpose of
putting a convergence check before the comparison rather than after it.

***** Verdict

*Score is accepted as a primitive and the head §3.3 specified is rejected.*

- The frozen donor supports Score well: 0.867 held-out against a 0.200 chance
  baseline, on five unseen scenarios.
- It does so compositionally: 0.820 on a subset where no bag of words can pass
  0.600, with 0.960 on the lexical half that proves nothing.
- The cumulative-link head loses to a plain softmax by 0.360 MAE with the
  interval excluding zero, so it is dropped -- an outcome §7's risk table
  pre-authorised ("P2 may drop it") and which is recorded rather than retried.

What this does not establish: anything about deployment, anything about messy
input, and the retained head's calibration, which is named above as an open

**** Calibration of the retained head -- pre-registered 2026-09-21

Written and committed before the calibrator was run on the encoded states, and
it closes the open item the verdict above names.  The subject is the *nominal*
head, the one gate 2 selected; the ordinal head's calibration is already
reported and belongs to a head that was dropped.

***** What is measured, and why it is not ECE

P3 established that ECE is not measurable on a held-out split this size: at
n=84 a model calibrated by construction scores 0.043-0.115 depending on bin
count, against a gate of 0.05.  Held out here is 75, so the same objection
applies with slightly more force.  The statistic is therefore P3's binning-free
one:

: CALIBRATION GAIN = NLL(uncorrected) - NLL(recalibrated)

with the recalibrator fitted out of fold, and judged against the band a
calibrated-by-construction model produces at the same split sizes.  A model
that needs no correction has nothing for the recalibrator to find, so its gain
sits near zero -- slightly below it, because applying a noisy correction to
fresh data costs a little.

***** The two questions, kept apart

P3 found that the rule as first written did not say which of two things it was
asking, and that the distinction decided the verdict.  Both are asked here:

- *A -- was the raw output calibrated?*  The out-of-fold temperature's gain on
  held-out answers it.  A gain outside the band means the recalibrator found
  real work, so the raw output was not calibrated.
- *B -- is the output calibrated after the temperature is applied?*  This is
  the acceptance question, because the phase ships a corrected model.

B cannot be answered by refitting on the same logits the first temperature saw:
the first is the minimiser there, so a second returns exactly 1 and the residual
gain is zero by construction rather than by merit.  It needs a split the first
calibrator never touched.

***** The split, fixed now

Held out is five scenarios: 3, 6, 9, 12, 15.  For question B the residual
calibrator is fitted on *scenarios 6 and 12* (30 examples) and the residual gain
is measured on *scenarios 3, 9 and 15* (45 examples).  By scenario, never
within one, for the reason every split here is by scenario.

Both bands are computed at the sizes they are compared against -- fit 165 /
eval 75 for A, fit 30 / eval 45 for B -- and *not* reused between them.
Comparing a statistic taken at one n against a floor taken at another is the
error that sank P3's ECE gate and it is not repeated.

***** The gates

- *Gate 0, convergence.*  The head and every out-of-fold head must finish below
  a gradient norm of 0.05.  Void otherwise, on the same terms that voided two
  probe runs.
- *Gate 1, the instrument can see.*  The 4x-overconfident control must fall
  entirely outside the calibrated band, in the same run, at both split sizes.
  If the two overlap, the statistic is blind here and no verdict is read from
  it -- a band that admits everything is not evidence.
- *Gate 2, acceptance.*  Question B's residual gain falls inside the 5-95% band
  of the calibrated-by-construction model at n=45.

***** Reported, not gated

- Question A's verdict, which is informative either way and is not the
  acceptance question.
- Accuracy before and after the temperature.  These must be *equal*: dividing
  every logit by a positive number preserves their order, so the argmax cannot
  move.  That is the property §4.2 assumes and the ordinal head broke, and it
  holds for the softmax -- =test/score-test.el= checks it over 3200 cases at
  four temperatures.  If the real run disagrees, the run is wrong, not the
  proof.
- ECE, with its bin count and n printed beside it, so it cannot be quoted
  against a figure measured under a different scheme.
- The fitted temperature and whether it rests on a search bound.

***** What would make this fail

Stated in advance so the result cannot be read as unfalsifiable: a temperature
far from 1 with question A's gain far outside its band, followed by a residual
gain that is *also* outside the band at n=45, would mean the correction did not
land and Score ships an uncalibrated head.  That is a real possibility -- the
ordinal head's own temperature came back at 4.24 with a gain of +1.09 against a
band of [-0.022, +0.011], which is exactly that picture before correction.

***** The verdict had to be re-measured before it could be believed

The first reading used 400 draws to estimate the band.  The post-hoc
diagnostic then computed the *same* band -- same sizes, same construction,
different seed -- and returned a 95th percentile of +0.0268 where the run had
returned +0.0160.  The observed gain is +0.0253: above one and below the
other.  The verdict was being decided by the simulation's seed.

*A statistic was compared against a threshold that had no error bar on it.*
That is the same fault this repository keeps finding, and this time it is in
the statistic built to replace ECE after P3 showed ECE could not be measured
at this n.  Estimating a committed quantity more precisely is not amending the
rule, so it was re-estimated: 12000 draws, with a bootstrap interval on the
percentile itself.

: 5th  percentile  −0.0950   95% CI [−0.0986, −0.0913]
: 95th percentile  +0.0201   95% CI [+0.0192, +0.0213]

+0.0253 clears the upper end of the threshold's own interval, so the call is
now the head's and not the simulation's.  *FAIL, robustly.*  Both 400-draw
readings were imprecise; neither was the number.

***** Two explanations were offered and both were refuted

A and B disagree about the same output -- the corrected logits are the raw ones
scaled by 0.946, which is very nearly not scaled at all.  Two mechanisms were
proposed, each named before it was tested, and each tested in a form that could
refute it.  Both were refuted.

1. *Clustering.*  B's band draws its halves as independent examples while the
   real halves are scenarios, and fifteen sentences sharing a subject are not
   fifteen independent draws -- so perhaps the band was simply too narrow.
   *No.*  All ten ways of choosing two held-out scenarios as the fit half give
   a residual temperature between 1.10 and 1.62, every one asking to flatten,
   and seven of the ten land above the band.  A band that models the clustering
   explicitly, with a per-group offset swept rather than estimated, barely
   widens.  The residual is systematic.
2. *Cross-validated under-correction.*  Each fold head fits on about seven of
   eleven training scenarios and the shipped head fits on all eleven; more data
   makes a head sharper, so perhaps the fold heads simply were not yet as
   overconfident as the shipped one.  *No, and the direction is backwards:*

   | folds | scenarios per fold head | out-of-fold T |
   |-------+-------------------------+---------------|
   |     2 |                       6 |         1.005 |
   |     3 |                       8 |         0.946 |
   |     5 |                       9 |         0.736 |
   |    11 |                      10 |         0.809 |

   A temperature fitted directly on the held-out logits is 1.313.  If the
   hypothesis held, more folds would walk toward it; they walk away from it.

***** What is established, and what is not

*Established.*  The pipeline Score would ship is not calibrated, and the
failure is in the procedure rather than in the head's potential.  The
out-of-fold temperature measured on the training split points the *opposite
way* from the correction the held-out scenarios need -- 0.74 to 1.01 against
1.31 -- so the calibrator is being fitted where the miscalibration is not.
P3's recipe, which worked for Noul, does not transfer to this head on this
data.

*Not established.*  Why.  Both mechanisms offered were tested and refuted and
the third is not in hand, so the honest state is an unexplained disagreement
rather than a plausible story with a diagram.  Also not established: whether
the head *could* be calibrated by a better-placed calibrator.  The direct
held-out temperature of 1.313 exists and would clearly help, but it has seen
the data it would be judged on, so it is a target and not a result.

***** What a re-test needs, and why it is not run here

Three-way scenario splits: train, calibrate, test, with the calibrator fitted
on scenarios the head did not train on *and* the test never sees.  This dataset
has five held-out scenarios, which is the binding constraint on every marginal
call in this phase -- question B's fit half is two of them.

Re-running gate 2 under a better temperature is not done, and the reason is
not fastidiousness: the gate has been taken, and taking it again with a
knowingly better instrument after seeing which way it fell is how a
pre-registration becomes decoration.  A re-test is a new pre-registration with
more scenarios, and it is named here as the follow-up rather than performed as
a correction.

**** Calibration re-test -- pre-registered 2026-09-21

The follow-up named above, written before the twenty new scenarios were
encoded.  It replaces nothing: the first attempt's FAIL stands on its own
terms, and this is a differently-built test of the same question.

***** Why a re-test at all, stated harder than last time

The first attempt's real defect was not its threshold.  Measured afterwards on
stubs, at its split sizes of 30 fit / 45 eval:

| calibrate/test | band [5%, 95%]     | p95 CI width | power 1.25x | power 1.5x |
|----------------+--------------------+--------------+-------------+------------|
| 30/45          | [−0.1059, +0.0206] |       0.0049 |       0.245 |      0.597 |
| 120/120        | [−0.0259, +0.0064] |       0.0019 |       0.603 |      0.932 |
| 180/180        | [−0.0162, +0.0047] |       0.0010 |       0.694 |      0.958 |

*At 30/45 a model 1.25x overconfident was caught one time in four.*  That test
was not one whose band was too narrow; it was one too weak to have been worth
reading in either direction, which is harder to notice than a wrong threshold
because nothing about it looks broken.  A FAIL from it and a PASS from it would
have carried about the same information.

***** The split, fixed now

Thirty-six scenarios, fifteen sentences each.  Three ways, disjoint by
scenario, defined so the assignment is computable rather than listed:

- *test* -- scenario id divisible by three.  Twelve scenarios, 180 examples.
- *calibrate* -- of the remaining twenty-four in id order, every third.  Eight
  scenarios, 120 examples: ids 4, 8, 13, 17, 22, 26, 31, 35.
- *train* -- the other sixteen, 240 examples.

The head fits on train alone.  The temperature fits on *calibrate*, which the
head never trained on and the test never sees.  That is the one structural
change from the first attempt, where the calibrator was fitted out of fold on
the training split and turned out to point the opposite way from what the
held-out scenarios needed.

The test set contains the whole of the first attempt's held-out set, so the
accuracy figures remain comparable; no test scenario has ever been in any
training split.

***** Why these sizes

Measured on stubs at 2500 draws, over the four three-way splits of thirty-six
scenarios that were actually available:

| train/cal/test | calibrate/test |    p95 CI | power 1.25x | power 1.5x |
|----------------+----------------+-----------+-------------+------------|
| 18/6/12        | 90/180         |    0.0014 |       0.648 |      0.942 |
| 20/6/10        | 90/150         |    0.0013 |       0.578 |      0.931 |
| *16/8/12*      | *120/180*      |  *0.0010* |     *0.693* |    *0.948* |
| 16/10/10       | 150/150        |    0.0015 |       0.679 |      0.936 |

16/8/12 is better than 16/10/10 on every column at the same training size, so
it is not a trade.  Tilting toward the test half beats tilting toward the
calibrate half throughout -- 180/60 falls to 0.455 where 60/180 holds 0.555 --
which is what a calibrator fitting one scalar against an evaluator estimating
a mean should do.

***** Declared power, before the result exists

*Power against the effect actually suspected is mediocre and no allocation
fixes it.*  The temperature fitted directly on the first attempt's held-out
logits was 1.313, which falls between the two sweep points: power is 0.693 at
1.25x and 0.948 at 1.5x, so somewhere near 0.8 at the size in question.  Power
against 1.25x never passes 0.694 at any size this dataset can reach, because
that is a property of an NLL gain with a one-parameter recalibrator and not of
the split.

Therefore *INDETERMINATE is a foreseen outcome of this test, not a failure of
it*, and saying so afterwards would be an excuse rather than a finding.

***** The verdict is three-valued

The first attempt read a FAIL off a threshold whose own uncertainty straddled
the observed value.  So:

- *PASS* -- the gain lies inside the band, and outside the bootstrap interval
  of the nearer percentile.
- *FAIL* -- the gain lies outside the band, and outside that interval.
- *INDETERMINATE* -- the gain lies inside the bootstrap interval of the
  percentile deciding it.  The call would then belong to the simulation rather
  than to the head, and neither word is said.

The band is estimated from at least 12000 draws with a bootstrap interval on
the percentile itself, and both are printed.  A verdict reported without the
threshold's error bar is not reportable.

***** The gates

- *Gate 0, convergence.*  The head finishes below a gradient norm of 0.05.
- *Gate 1, the instrument can see.*  The 4x-overconfident control clears the
  calibrated band, at the actual split sizes.
- *Gate 2, acceptance.*  The gain on *test*, after the temperature fitted on
  *calibrate*, is PASS by the three-valued rule above.

***** Reported, not gated

- The temperature fitted on calibrate, beside the one fitted out of fold on
  train and the one fitted directly on test.  The first attempt's finding was
  that the second points the wrong way; whether the first agrees with the third
  is the diagnostic that says whether the structural change worked.
- Accuracy and MAE across the temperature.  They must be *equal*; the argmax
  cannot move under a positive scalar divide.
- ECE with its bin count and n, not as a gate.
- Held-out accuracy and the hard-subset figures on the enlarged test set, so
  the Score result itself is re-measured at n=180 rather than n=75.

***** What would make this fail

A temperature on calibrate far from 1, a gain on test above the band's upper
percentile and clear of that percentile's interval.  That would mean the
correction still does not land even when the calibrator is fitted on scenarios
of the right kind, and the conclusion would be that this head cannot be
calibrated by a single temperature -- which is a real finding and a different
one from "the procedure was pointed at the wrong data".


** P3 -- calibration proper

Proper-scoring-rule objective, temperature and vector scaling, the full gate of
§4.3 with its negative control.

Accept when: ECE on a named held-out set is below a threshold fixed *before* the
run, with binning scheme and =n= stated, and the miscalibrated control is red.
*** Pre-registration, written and committed before the run

/This subsection was committed before the measurement it judges.  The criterion
says "a threshold fixed before the run", and a threshold chosen after seeing
the number is not one; the git history is what makes the claim checkable./

*Evaluation set.*  The P1 held-out split: 84 examples, 42 minimal pairs, split
by pair from the 252-example Noul set.  Features are mid-depth last-token
states, the P1 winner.  No re-encoding -- the states on disk are the same ones
P1 reported from.

*Metric.*  Top-label ECE, *10 equal-width bins*, reported with =n= beside it,
plus the reliability table.  Equal-mass is reported as a secondary and is not
the gate.

*Calibrators.*  Both fitted on *out-of-fold logits from the training split*,
three folds by pair, never on the held-out set and never on the training
logits the head has already separated -- the two mistakes P1 made in order.

*The thresholds, fixed now:*

1. *Gate.*  Held-out ECE after calibration =<= 0.05=.  This is the
   repository's standing `nso-default-ece-threshold', not a number picked to
   suit.  P1 already reached 0.040 with temperature alone, so this clause is
   nearly free and is not where the phase is decided.

2. *The real question.*  Vector scaling is adopted over temperature only if it
   *both* lowers held-out ECE by at least 0.005 *and* does not lower held-out
   accuracy at all.  Temperature cannot change an answer; vector scaling can,
   and a calibration step that quietly reclassifies examples has to pay for
   it.  If it lowers ECE but costs accuracy, temperature stays and this doc
   says so.

3. *Negative control.*  The 4x-overconfident stub must come out red on the
   same gate, at the same bin count, in the same run.  A gate that only ever
   passes is not a gate.

4. *Honesty clause.*  Per-difficulty ECE (antonym against compositional) is
   reported whatever it shows.  If the model is well calibrated overall and
   badly calibrated on the harder subset, that is the finding, and it is the
   one a confidence-gated caller would care about most.

*What would make this phase fail:* held-out ECE above 0.05 after both
calibrators; or the negative control coming out green; or a leak found in the
out-of-fold construction.

  fitted intercept is -0.005 and it moves *zero* of 84 answers.  The rule --
  adopt only on an ECE gain of 0.005 with no accuracy cost -- returns "keep
  temperature", which is the right answer for a reason the rule states rather

*** Choosing a bin count, which answered a different question

The next move looked like arguing a bin count on its own terms instead of
inheriting one.  The rule was fixed first, and on synthetic stubs only, so it
could not be tuned to the answer: /the largest bin count whose bias stays at
or below 0.02 while still failing a 4x-overconfident control in 95% of draws/.
Bias here is not an estimate of anything -- a stub calibrated by construction
has a true ECE of zero, so whatever the estimator reports on it is bias.

At =n = 84=, nothing qualifies (=tools/p3-bincount.el=, 200 draws per cell):

|------+--------+-------+------------|

|   10 | 0.0823 | 1.000 | too biased |
|   20 | 0.1154 | 1.000 | too biased |

*A perfectly calibrated model of this size scores 0.043 to 0.115.*  The gate

- Three bins would have passed at 0.035.  That would have been buying a pass

- *P1's headline ECE of 0.040 is inside the noise.*  At five bins the floor is

  that is calibrated by construction/.  It was never evidence of good

|  200 | 0.0425 |  0.0496 |
|  500 | 0.0249 |  0.0303 |
| 1000 | 0.0184 |  0.0227 |
| 2000 | 0.0127 |  0.0155 |
| 5000 | 0.0077 |  0.0097 |

Power against the 4x-overconfident control is 1.00 throughout, so the binding
constraint is bias alone.  Ten bins needs about =n = 2000=; five needs about
=n = 1000=.  Against 84 held-out examples that is twelve to twenty-four times
the data, more than the whole 252-example set.

*** Calibration without bins, which works at this n

A proper scoring rule has no bins, but NLL alone does not isolate calibration
-- it mixes calibration with sharpness.  Separating them needs no bins either:

: calibration gain = NLL(uncorrected) - NLL(recalibrated)

with the recalibrator fitted on a separate split.  A model that needs no
correction has nothing to gain and in fact loses a little, because a
temperature fitted on finite data is noisy and a noisy correction applied to
fresh data costs something.  A miscalibrated one gains in proportion.

Measured at exactly the P1 geometry -- 168 train, 84 held-out, 400 draws
(=tools/p3-gain.el=):

| model                      |   mean gain | 5%..95%            |
|----------------------------+-------------+--------------------|
| calibrated by construction |     -0.0034 | [-0.0216, +0.0074] |
| 4x overconfident           |     +0.4109 | [+0.1771, +0.6958] |

The sign of the first row is the theory showing up in the data: a correction
fitted for a model that needs none is noise, and noise costs.

*The P3 run measured a gain of 0.0220 on the real model* -- NLL 0.3830 to
0.3610.  Against the calibrated-by-construction distribution that sits at the
99.5th percentile, outside what chance produces here.  So the model *was*
miscalibrated, temperature *did* remove it, and that is demonstrable at the
sample size where ECE could say nothing at all.

*This is an interpretation, not a gate.*  The 0.0220 was computed in the P3
run before this analysis existed, so a threshold set now could have been set
around it.  What the stubs supply is the floor and the spread; the comparison
is the reader's to make.  For the next phase the rule /can/ be pre-registered,
and should be: accept when the held-out recalibration gain falls inside the
5-95% band of a calibrated-by-construction stub at that =n=, with the
4x-overconfident control outside it in the same run.

=test/calibration-test.el= pins both directions at =n = 84= and, beside them,
the ECE floor of 0.082 that made the switch necessary.

*** What would legitimately change the verdict

More held-out data, or a bin count justified by =n= and fixed *before* the
next run.  Both are honest; choosing between them after seeing this table is
not, so the choice belongs to whoever starts the next phase, in writing, first.

A rule of thumb worth pre-registering rather than inventing later: bins such
that the expected count per occupied bin stays above roughly 30, which at
n=84 means about three.  That is a smaller number than this phase used and it
would have passed, which is exactly why it must be argued for on its own terms
and not adopted here.

*** Verdict: ACCEPTED by the pre-registered binning-free rule

The rule as committed: /accept when the held-out recalibration gain falls
inside the 5-95% band of a calibrated-by-construction stub at that n, with the
4x-overconfident control outside it in the same run./

Applying it needs one distinction the rule does not spell out, and the
distinction decides the verdict.  Two questions hide inside "is it
calibrated":

- *A -- is the head's raw output calibrated?*  The out-of-fold temperature's
  gain answers it.
- *B -- is the output calibrated after that temperature is applied?*  This is
  what "calibration proper" has to mean, because the phase ships a calibrated
  model and not a raw one.  It is the acceptance question.

B cannot be answered by refitting a temperature on the logits the first one
was fitted on: the first is the minimiser there, so the second returns exactly
1 and the residual gain is zero by construction rather than by merit.  It
needs data the first calibrator never saw, so the held-out split is halved by
pair -- the residual calibrator is fitted on one half and measured on the
other.  =n= falls to 42 a side, so the stub band is *recomputed at 42* rather
than reused from 84.  Comparing a statistic at one =n= against a floor
measured at another is precisely the error that sank the ECE gate.

| question                   |    gain | band at that n       | reading         |
|----------------------------+---------+----------------------+-----------------|
| A, raw output (n=84)       | +0.0220 | [-0.0384, +0.0110]   | *outside* -- not calibrated |
| B, after temperature (n=42)| -0.0121 | [-0.0670, +0.0193]   | *inside* -- calibrated |

Controls, in the same run: the 4x-overconfident stub bands are [+0.1727,
+0.6713] at =n=84= and [+0.0675, +0.7654] at =n=42=, both clear of the
calibrated band.  The rule can distinguish, which is what makes a reading
inside the band mean something.

*P3 is ACCEPTED.*  The head's raw probabilities were miscalibrated, the
out-of-fold temperature removed it, and a fresh calibrator fitted on unseen
held-out data finds nothing left to remove -- it loses 0.0121, which is the
sign a correction takes when there is nothing to correct.

*What the acceptance does not cover.*  The original gate was ECE =< 0.05 at
ten bins and that gate *failed*, at 0.0796.  It is not withdrawn and not
reinterpreted: it was shown afterwards to be unmeasurable at this =n=, which
makes it uninformative rather than passed.  This acceptance rests on a
different statistic, chosen because it has no binning floor, and pre-registered
before this run.  Anyone reading "P3 accepted" should read both rows above and
the two sections before them.

Still standing from the run itself, and unaffected by which statistic judges
it: temperature improves the proper score while leaving accuracy untouched;
vector scaling moves zero of 84 answers and is not adopted; and calibration is
worse on the compositional subset (ECE 0.1138) than on the antonym one
(0.0798), which is the number a confidence-gated caller should care about most
and the one this phase would most like more data for.

fall back to the existing path below threshold.

*Out of scope.*  Section 8 settles the definition of done as (A), the spike,

** Cross-cutting: NeLisp portability

The CPU path should run under the NeLisp standalone reader, as =nelisp-llm='s
does.  The known gaps and their absorbed workarounds are already catalogued
(=nelisp-llm/lisp/nl-llm-compat.el=); the one that matters most here is that
NeLisp's =exp= returns NaN for very negative arguments, which silently turns a
masked softmax into NaN while max-accumulating test helpers report
=PASS maxdiff=0.00e+00=.  Any test helper written in this repository counts NaN
as a failure from its first line.

* 8. Definition of done -- settled: (A) spike

Settled 2026-09-19.  The two readings that were open:

- *(A) Spike.*  Done = the method demonstrably works at toy scale, with honest
  numbers including the negative ones.  P0-P3.  The deliverable is knowledge.
- *(B) Production.*  Done = anvil's routing actually runs through this, with a
  fallback path and an operational confidence threshold.  P0-P4, and P4 carries
  reliability work not costed above.

*(A) is the scope of this project.*  It is complete when P3's acceptance
criterion is met, and it is complete whether the answer is encouraging or not: a
spike that establishes "a 0.6B causal donor does not pool into a decision
encoder good enough to be worth calibrating" has met its definition of done, and
that result gets written up here rather than worked around.

Two consequences that bind the work:

- *No production obligations are assumed.*  Latency budgets, failure modes,
  rollback paths and operational thresholds belong to (B).  Building them anyway
  is scope creep and costs the spike the speed that is its only advantage.
- *No production claims may be made.*  Nothing here may be described as ready to
  route anvil traffic on the strength of P0-P3.

Reopening the question is allowed and is a new decision, recorded by revising
this section -- not something an encouraging P3 result does on its own.

* 10. Closing the spike

Written 2026-09-20, after P3's verdict.  Scope (A) is met: P0-P3 ran, the
numbers are all here including the ones that went the wrong way, and this
section is the deliverable.

** 10.1 What the spike answered

The question was whether a frozen 0.6B causal donor plus a typed head
reproduces what a System One model *does* -- not whether it matches Jev, which
is closed and cannot be matched from outside.  §1 split the vendor's claims
into three reproducible in kind and one not.  Against that split:

| claim                             | reproducible?   | outcome                                                                                                             |
|-----------------------------------+-----------------+---------------------------------------------------------------------------------------------------------------------|
| (a) output typed, always valid    | structurally    | delivered -- the gate rejects every ill-typed answer the suite constructs, and mutation checks show it can still fail |
| (b) one parallel pass, no tokens  | architecturally | delivered -- one forward pass per decision                                                                          |
| (c) probabilities calibrated      | in effect       | delivered at n=84, by a binning-free rule (P3)                                                                      |
| (d) orders of magnitude cheaper   | no              | not claimed; no timing number in this repository is a claim about Jev                                               |

Three of four, at toy scale.  The fourth was ruled out before any code existed
and nothing here walked it back.

** 10.2 The measurements that stand

| phase | question                                       | result                                                                       |
|-------+------------------------------------------------+------------------------------------------------------------------------------|
| P0    | can the harness fail?                          | yes -- negative controls red, 129 checks green                               |
| P1    | does a frozen donor pool into a decision head? | yes -- 0.857 held-out against a 0.500 majority baseline                      |
| P1    | words, or composition?                         | composition -- 0.792 on compositional pairs where bag-of-words scores 0.507  |
| P2    | does the same encoder support Choice?          | not accepted -- 0.375 on held-out topics, 0.25 chance                        |
| P3    | is the head calibrated?                        | accepted -- corrected output inside the calibrated band, control separated   |
| Score | does a frozen donor support an ordinal scale?  | yes -- 0.867 held-out against a 0.200 chance baseline                       |
| Score | word order, or word identity?                  | order -- 0.820 where no bag of words can pass 0.600                         |
| Score | does §3.3's cumulative-link head earn its keep? | no -- it loses to a plain softmax by 0.360 MAE, interval excluding zero     |

The compositional number is the load-bearing one.  =failed to lose= and
=failed to win= share every content word; a model scoring 0.792 on that subset
is not matching vocabulary.  It is the only row in the table that could not
have come out of a lookup table, and it is what makes the category look real
at this scale.

** 10.3 What this document got wrong

Four claims written before measurement were contradicted by measurement.  All
four are corrected in place above rather than quietly dropped:

1. *§3.2 assumed the final layer.*  Mid depth wins.  The final layer of a
   causal LM is specialised for next-token prediction, which is the wrong job.
2. *§3.2 expected the learned attention pool to win.*  It is undecided: the
   result inverts under feature rescaling, so the experiment measured the
   optimiser, not the pooling.  P1's claim that the learned pool "loses" was
   withdrawn.
3. *§4.3 had the ECE bias backwards.*  Few samples per bin biases ECE *away*
   from zero, not toward it; coarse bins bias toward zero by cancellation.
   Measured on stubs calibrated by construction: 0.0876 at n=100 against
   0.0109 at n=4000.
4. *§4.3's gate was unmeasurable at this n.*  At n=84 a perfectly calibrated
   model scores 0.043-0.115 depending on bin count, against a 0.05 gate.  The
   gate needs n around 2000 at ten bins.  P1's reported 0.040 was inside the
   noise floor as well, and was measured at five bins where the gate was ten.

The fourth is why P3 is accepted on a binning-free statistic, and why the ECE
gate is neither withdrawn nor treated as passed: it was shown uninformative,
which is a different thing from being met.

** 10.4 Why P2 was not accepted, specifically

Choice reached 0.375 against 0.25 chance on four entirely held-out topics --
above chance, below useful.  The diagnosis is narrower than "Choice does not
work":

- State and option embeddings come from the same frozen encoder, whose states
  have mean pairwise cosine 0.923.  The geometry is anisotropic enough that a
  diagonal map has little room to separate topics it never saw.
- Replacing bare topic names with descriptions in the request register helped,
  which says part of the gap is register mismatch rather than capacity.
- Two remedies were identified and not run: more than diagonal capacity, and
  whitening rather than per-axis standardisation.

So the honest statement is that *this* encoder with *this* head does not
support Choice on unseen topics -- not that option scoring is the wrong
architecture.  §3.1's argument for option scoring over slot classification is
untouched: a slot classifier could not have been evaluated on held-out topics
at all.

** 10.5 What it cost, and what was declined

The full encode plus probe went from 190 minutes to 59 for 252 examples, in
three measured steps: IPC batching (39.7 to 16.3 s/example), byte-compiling
this repository's lisp (attention path 54 to 10 minutes), and byte-compiling
the sibling lisp into =build/elc= (16.3 to 10.0 s/example).

Two costs were declined deliberately, and are recorded rather than left
silent: GPU compiled batches (worth at most another 1.5x, and the work belongs
in the sibling repository) and native compilation (measured at 1.34x, not
worth the build complexity for a spike).

** 10.6 Method faults worth carrying forward

Three patterns recurred in this spike's own process.  They are recorded
because they are the part of the work that transfers:

1. *Synthetic tests hid real-scale failures* (four times, the last in Score).
   Every suite here now carries at least one case at real scale or with real
   geometry -- and Score showed that "real scale" has more than one axis: its
   smoke matched the states' magnitude, deliberately and with a comment saying
   why, while fitting at dim 64 against a real dim of 1024.  Half a lesson
   applied is how a fixture stays green through the failure it exists to catch.
2. *Fixed constants lost to a scale nobody checked* (five times).  It was
   always a step size until Score, where the step was fixed and the ITERATION
   COUNT was too: 600 iterations converged on synthetic ordinal data and left
   the real features at a gradient norm of 0.141 against a gate of 0.05.  The
   fix that works is not a better constant but no constant -- a line search for
   the step, a convergence criterion for the count.
3. *A check firing is not the check measuring the right quantity* (twice).
   The timing guard had a negative control and the control passed -- which
   confirmed the check fires below its threshold, not that timing was the
   right quantity to threshold.  The Platt assertion was green while Platt
   lost by 0.13 NLL, because it was written in the direction that cannot fail.

A fourth, from P3: comparing a statistic measured under one setting against a
floor measured under another -- five-bin ECE against a ten-bin gate, a band at
n=84 against a gain at n=42 -- is the same error every time, and it is easy to
commit in the very paragraph warning about it.

** 10.7 What is not established

- *Nothing about deployment.*  n=84 held out, author-written data, no LoRA,
  one donor, one language.  §8's prohibition on production claims stands.
- *The compositional subset is the weakest actionable point*: ECE 0.1138
  against 0.0798 on antonym pairs.  The head is least calibrated exactly where
  it is most interesting.  More data is the remedy, not a different
  calibrator.
- *Score is built, its architecture argument did not survive, and the head it
  ships is not calibrated.*  §2's signature is implemented and the primitive
  works; §3.3's cumulative-link head is rejected by the rule §3.3 itself set,
  and the head behind Score is now the plain softmax.  That head's calibration
  was then pre-registered and measured, and it failed: the out-of-fold
  temperature points the opposite way from the correction the held-out
  scenarios need, so P3's recipe does not transfer here.  Two explanations were
  offered and both refuted, so the disagreement is recorded as unexplained.  A
  re-test needs three-way scenario splits and more scenarios than this dataset
  has.
- *Nothing here says anything about Jev.*  The category is reproducible; the
  artefact is not, and no result above should be read as a comparison.

The spike is complete under §8.  Reopening it for (B) remains a new decision,
taken by revising §8 -- not by pointing at P1's 0.857.
